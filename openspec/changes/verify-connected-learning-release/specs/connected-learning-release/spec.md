## ADDED Requirements

### Requirement: N25 Behavioral fixtures
Regression fixtures SHALL cover packages, TypeScript/React, mixed boundaries, nested configuration, tiny source, ambiguity and limited DAZ coverage using synthetic data.

#### Scenario: N25 Behavioral fixtures behavior
- **WHEN** The regression suite runs
- **THEN** it asserts source graph, selection, teaching and persistence behavior without credentials

### Requirement: N26 Complete journey
Headless journey checks SHALL cover full review, map, contextual instructor, offline quiz, saved session, restart and comparison, plus failure/cancellation and narrow screens. Target contents SHALL remain unchanged.

#### Scenario: N26 Complete journey behavior
- **WHEN** A learner revisits after a server restart
- **THEN** drafts and history are restored and no target file was edited

### Requirement: N27 Real teaching acceptance owner
Existing L17 SHALL remain the owner of bounded authorised provider accuracy and observed beginner learning acceptance. Automated fixtures SHALL NOT replace factual inspection, beginner feedback or later recall.

#### Scenario: N27 Real teaching acceptance owner behavior
- **WHEN** Real inference or learner feedback is unavailable
- **THEN** L17 and N27 remain explicitly open with the exact next action

### Requirement: N28 Verified publication and daily use
Release SHALL require Windows regressions, strict OpenSpec validation, browser checks, private-data review, installed behavior and preserved learning data. Checkpoints MAY be published before release acceptance, but completion SHALL NOT be claimed or merged prematurely.

#### Scenario: N28 Verified publication and daily use behavior
- **WHEN** A real acceptance gate remains open
- **THEN** tested checkpoints may be pushed while release status remains incomplete

Evidence: 2/3 — approved intent and current implementation guide these scenarios; verification is recorded separately and real learning effectiveness is not established.
